This is just a little experiment in attempting to streamline development, where all a user has to worry about is logically making the code, as opposed to having to learn a framework, and not quickly iterate as a result.

InputManager is meant to have any inputs (Any dashboard buttons, controllers, and sensors optionally) So that those inputs can be used anywhere in the code. 
I do recommend that sensors be placed in their respective subsystems depending on their use cases. 
Logging the input manager is looking into being a feature as to help development.
